# Recipe: Wazuh 4.x rule 100201

myapp: repeated failures of admin

- Origin: `etc/rules/local_rules.xml:15`
- State: `RECIPE` (no direct translation)

## Why

- [`RM-R-FREQUENCY`](README.md#rm-r-frequency) (RECIPE): The rule counts events (frequency/timeframe). 5.x rules have no state: an Alerting monitor replaces it. Detail: from parent rule 100200.
- [`RM-R-PARENT-RECIPE`](README.md#rm-r-parent-recipe) (RECIPE): A parent rule is RECIPE, so this rule cannot be translated on its own either. Detail: parent rule 100200 is RECIPE (RM-R-FREQUENCY).
- [`RM-R-SHADOWING`](README.md#rm-r-shadowing) (AUTO): In 4.x only one rule alerts per event; in 5.x every matching rule produces a finding. This rule can now fire together with a parent or a sibling.

## What you need to do

1. Create the Alerting monitor in monitors/100201.json (Dev Tools: POST _plugins/_alerting/monitors). It counts the findings of the base rule; add an action to its trigger to be notified.
2. Apply the recipe of the parent first; this rule depends on it.
