# Recipe: Wazuh 4.x rule 100200

myapp: repeated failures from $(srcip)

- Origin: `etc/rules/local_rules.xml:10`
- State: `RECIPE` (no direct translation)

## Why

- [`RM-R-FREQUENCY`](README.md#rm-r-frequency) (RECIPE): The rule counts events (frequency/timeframe). 5.x rules have no state: an Alerting monitor replaces it. Detail: frequency=8 timeframe=120.
- [`RM-R-SHADOWING`](README.md#rm-r-shadowing) (AUTO): In 4.x only one rule alerts per event; in 5.x every matching rule produces a finding. This rule can now fire together with a parent or a sibling.

## What you need to do

1. Create the Alerting monitor in monitors/100200.json (Dev Tools: POST _plugins/_alerting/monitors). It counts the findings of the base rule; add an action to its trigger to be notified.

## Monitor

The definition is in `monitors/100200.json` (bucket-level monitor over `wazuh-findings-v5-*`; the build does not create it).
- window 300 s instead of 120 s: findings arrive one or two minutes late
